Sign-in credentials

How to get the Google and Apple credentials for sign-in on watercolourlove.de and in the native app (TASK-60, TASK-61). About 15 minutes each. Collect the values as you go; they all end up in config.php on the server. This page holds no secrets and is not published with the site.

Google

Open the Google Cloud console.

  1. In the project picker at the top, choose New project, name it "Watercolourlove" and select it.
  2. Open the Google Auth Platform and click "Get started".
    • App name: Watercolourlove
    • User support e-mail: your address
    • Audience: External
    • Contact e-mail: support@markus-freise.de
  3. On Branding:
    • Home page: https://watercolourlove.de/
    • Privacy policy: https://watercolourlove.de/privacy/
    • Terms: https://watercolourlove.de/terms/
    • Authorised domain: watercolourlove.de
    Skip the logo: uploading one starts a review by Google that takes days.
  4. Nothing to add. The app only asks for openid and email, which are basic scopes and need no review.
  5. On Audience, click Publish app so it goes from "Testing" to "In production". Without this, only test users you list can sign in. With basic scopes, publishing needs no verification.
  6. On Clients, click "Create client".
    • Type: Web application
    • Name: Watercolourlove Web
    • Authorised redirect URIs: https://watercolourlove.de/api/auth/google/callback
    • Optional, to test on the dev instance first: also https://watercolourlove.croeso.de/api/auth/google/callback
  7. Click Create and copy the Client ID and the Client secret. Newer consoles show the secret only once, so save it right away.

The app's Google sign-in goes through the website, so no separate iOS client is needed.

Apple

Open Certificates, Identifiers & Profiles in your developer account.

  1. It is shown under Membership details. Write it down (10 characters).
  2. Under Identifiers, open de.markusfreise.watercolourlove. Tick Sign In with Apple, leave it set to "Enable as a primary App ID" and save. If Xcode manages signing automatically, it picks up the change on the next build.
  3. Under Identifiers, Services IDs, click +, choose Services IDs and Continue.
    • Description: Watercolourlove Web
    • Identifier: de.markusfreise.watercolourlove.web
    • Click Continue, then Register.
  4. Open the Services ID you just created, tick Sign In with Apple and click Configure.
    • Primary App ID: Watercolourlove (de.markusfreise.watercolourlove)
    • Domains: watercolourlove.de (optionally also watercolourlove.croeso.de)
    • Return URLs: https://watercolourlove.de/api/auth/apple/callback (optionally also https://watercolourlove.croeso.de/api/auth/apple/callback)
    • Click Next, Done, Continue, then Save.
  5. Under Keys, click +.
    • Name: Watercolourlove Sign in with Apple
    • Tick Sign in with Apple, click Configure, choose the primary App ID Watercolourlove and save.
    • Click Continue, then Register.
    • Download the .p8 file. Apple offers the download only once. Note the Key ID (10 characters).
  6. Apple users can hide their address behind an @privaterelay.appleid.com address, and Apple forwards mail to it only from registered senders. Open Sign in with Apple for Email Communication (under Services, not Identifiers) and register support@markus-freise.de as a sender. The domain's SPF record must allow the server that sends the mail.

On the server

  1. Put the .p8 file on Mittwald outside the web root, for example next to the SQLite database, and run chmod 600 on it.
  2. In the API's config.php (template: server/config.example.php): 
    'google' => ['client_id' => '…apps.googleusercontent.com', 'client_secret' => 'GOCSPX-…'],
'apple' => [
    'client_id' => 'de.markusfreise.watercolourlove.web',
    'app_id'    => 'de.markusfreise.watercolourlove',
    'team_id'   => 'ABCDE12345',
    'key_id'    => 'XYZ9876543',
    'key_file'  => '/home/www/pXXXXXX/AuthKey_XYZ9876543.p8',
],

The buttons appear on their own once the values are there; nothing needs to be deployed. Google shows up as soon as its two values are filled in. Apple needs all four values and a key file it can read.

Never commit config.php or the .p8 key, and don't paste the secret or the key into a chat. When it is filled in, ask Claude to test both sign-ins against the real services.
